# План новых карточек / источников данных

> **Статус: реализовано.** Все 7 карточек ниже добавлены (EPIC, землетрясения
> USGS, Живое Солнце SDO, солнечный цикл, Луна и затмения, аврора на глобусе,
> поиск по архиву NASA), скрыты по умолчанию, покрыты тестами. Документ оставлен
> как история проектирования.

Все источники ниже проверены живым `curl` с заголовком
`Origin: https://dmitryweiner.github.io` (2026-08-02): либо отдают
`Access-Control-Allow-Origin: *`, либо CORS не нужен (обычный `<img>`,
либо вычисления без сети). Проект — статический сайт без бэкенда, поэтому
это обязательное условие.

Отбракованы по итогам той же проверки (CORS-заголовков **нет**, из браузера
недоступны): JPL SSD Fireball/Sentry/CAD (`ssd-api.jpl.nasa.gov`),
Helioviewer API, NASA Exoplanet Archive TAP, Open Notify (только HTTP →
mixed content). Возвращаться к ним только если появится прокси
(например, Cloudflare Worker).

## 1. EPIC — Земля целиком из точки L1 (DSCOVR)

**Что:** ~десяток полнодисковых фото Земли за день с камеры DSCOVR/EPIC;
карточка со слайдером/автопрокруткой по кадрам дня (видно вращение Земли).

**API:** `https://epic.gsfc.nasa.gov/api/natural` — без ключа (прямой хост,
не `api.nasa.gov`), CORS `*`. Отдаёт массив
`{ image, date, centroid_coordinates: {lat, lon}, ... }`.
Сама картинка строится по шаблону:
`https://epic.gsfc.nasa.gov/archive/natural/YYYY/MM/DD/png/<image>.png`
(дату брать из поля `date` записи; есть и `jpg`-вариант полегче).

**Реализация:**
- `src/api/epic.ts` — fetch+parse по образцу `apod.ts`: инжектируемый
  `fetch`, валидатор-предикат вместо `as` (паттерн `readCache`).
  Функция сборки URL картинки — чистая, покрыть vitest-тестом.
- `src/cards/EpicCard/` — по образцу `ApodCard` (картинка + подпись),
  плюс слайдер по кадрам (обычный `<input type="range">`) и подпись с
  временем кадра через `formatTimestamp.ts`.
- `useApiResource` с TTL ~1 час (набор кадров меняется раз в сутки,
  публикуется с лагом в 1–2 дня — брать последний доступный день,
  который и возвращает `/api/natural`).
- Настройка карточки: `{ kind: 'number' }` — интервал автопрокрутки, или
  без настроек в первой версии.
- Регистрация в `cardRegistry.ts` как скрытая по умолчанию (`y ≥ 6`),
  иначе придётся синхронизировать `DEFAULT_VISIBLE` в `scripts/smoke.mjs`
  и `tests/app.test.tsx`.

**Трудозатраты:** низкие. Лучшее соотношение «вау/код».

## 2. Землетрясения USGS на 3D-глобусе

**Что:** землетрясения за сутки/неделю маркерами на глобусе, размер/цвет по
магнитуде. Дополняет EONET (в котором землетрясений нет).

**API:** `https://earthquake.usgs.gov/earthquakes/feed/v1.0/summary/2.5_day.geojson`
— GeoJSON, без ключа, CORS `*`, обновляется ежеминутно. Есть варианты лент:
`{all|1.0|2.5|4.5|significant}_{hour|day|week}.geojson`.

**Реализация:**
- `src/api/usgsQuakes.ts` — парсинг GeoJSON: `features[].geometry.coordinates`
  (lon, lat, depth) + `properties.mag`, `properties.place`, `properties.time`.
- `src/cards/QuakesCard/` — клон структуры `NaturalEventsCard`: тот же
  `createEarthScene`, маркеры через `setMarkers` (id/цвет/подпись уже
  поддерживаются; подписи сами скрываются за горизонтом — depth-tested
  спрайты). Цвет — по магнитуде, легенда как в Natural Events.
  Если маркеров много и захочется ховер-тултипов вместо постоянных
  подписей — переиспользовать механику `setFirePoints` (point cloud +
  raycast-тултип с горизонт-тестом).
- Настройки: `{ kind: 'multiselect' }` — порог магнитуды/период ленты
  (каждая комбинация = отдельный URL, кэшировать по URL).
- TTL ~5–10 минут. Карточка WebGL → добавить в список canvas-проверок
  `scripts/smoke.mjs`.

**Трудозатраты:** низкие (вся 3D-инфраструктура уже есть).

## 3. Аврора на глобусе (OVATION JSON) — апгрейд существующей карточки

**Что:** вместо/рядом со статичной картинкой — овал полярных сияний прямо на
3D-глобусе точечным облаком с прозрачностью по вероятности.

**API:** `https://services.swpc.noaa.gov/json/ovation_aurora_latest.json` —
CORS `*`, без ключа. Формат: `{ "Observation Time", "Forecast Time",
coordinates: [[lon, lat, aurora], ...] }` — сетка 1°×1°, `aurora` =
вероятность 0–100.

**Реализация:**
- Парсер добавить в `src/api/swpc.ts` (тот же хост, там уже живут Kp и
  solar wind). Отфильтровать нули — их подавляющее большинство.
- Вариант A (минимум): переключатель «карта/картинка» в текущей
  `AuroraForecastCard`, точки через `setFirePoints` (готовое облако точек
  с `sizeAttenuation:false`), цвет зелёный, alpha по вероятности.
  Если `setFirePoints` не поддерживает per-point alpha — расширить его
  или добавить параллельный `setAuroraPoints` в `earthScene`.
- Вариант B: отдельная карточка `aurora-globe`, а старая остаётся как есть.
- TTL ~5 минут (продукт обновляется каждые ~5 мин).

**Трудозатраты:** средние (возможно, придётся чуть расширить `earthScene`).

## 4. Солнечный цикл — число пятен и F10.7

**Что:** график солнечной активности за годы: наблюдения + официальный
прогноз, маркер «сейчас». Наглядно виден максимум 25-го цикла.

**API (оба CORS `*`, без ключа, хост уже используется в `swpc.ts`):**
- `https://services.swpc.noaa.gov/json/solar-cycle/observed-solar-cycle-indices.json`
  — помесячно: `{ "time-tag": "YYYY-MM", ssn, smoothed_ssn, f10.7, ... }`.
- `https://services.swpc.noaa.gov/json/solar-cycle/predicted-solar-cycle.json`
  — прогноз в том же духе.

**Внимание:** это массив объектов, а не `[header, ...rows]` — по правилу из
CLAUDE.md формат сверен с живым эндпоинтом; ключ `f10.7` содержит точку —
доставать через индексный доступ по строке, не через деструктуризацию.

**Реализация:**
- Парсер в `src/api/swpc.ts` + типы.
- `src/cards/SolarCycleCard/` — по образцу `KpIndexCard` (SVG-бары/линия
  + `TimeAxis`). Две серии: observed (сплошная) и predicted (пунктир).
- TTL большой (данные помесячные): 6–24 часа.
- Настройка `{ kind: 'number' }`: горизонт в годах (например 5–30).

**Трудозатраты:** низкие. Без 3D — тестируется обычным vitest.

## 5. Живое Солнце (SDO) — карточка-картинка

**Что:** актуальный снимок Солнца в выбираемых длинах волн (корона 193 Å,
пятна HMI и т.д.), обновление каждые ~15 минут.

**Источник:** прямые `<img>`-URL (CORS не нужен), например:
`https://sdo.gsfc.nasa.gov/assets/img/latest/latest_1024_0193.jpg`
(варианты: `0171`, `0193`, `0304`, `0131`, `HMIIF` — видимый свет с
пятнами, `HMIB` — магнитограмма; размеры 512/1024/2048).

**Реализация:**
- Без `src/api/`-модуля вообще — паттерн `AuroraForecastCard`: `<img>` с
  cache-busting query-параметром и таймером обновления.
- Настройка `{ kind: 'multiselect', options: [длины волн] }` — показывать
  выбранные снимки сеткой. Это готовый кейс под существующий механизм
  `listSetting`.
- Тем же паттерном можно добавить **Землю с геостационара**:
  `https://cdn.star.nesdis.noaa.gov/GOES19/ABI/FD/GEOCOLOR/1808x1808.jpg`
  (GOES-19 full disk GeoColor) — либо отдельной карточкой, либо ещё одной
  опцией мультиселекта.

**Трудозатраты:** минимальные из всего списка.

## 6. Луна и затмения — вообще без сети

**Что:** текущая фаза Луны (иконка/рендер + процент освещённости),
расстояние (апогей/перигей), даты ближайших лунного и солнечного затмений.

**Источник:** никакого API — `astronomy-engine` уже в зависимостях:
`MoonPhase`, `Illumination`, `SearchLunarEclipse`,
`SearchGlobalSolarEclipse`, `SearchLunarApsis`.

**Реализация:**
- `src/astro/moonInfo.ts` — чистая математика (правило: никаких
  Three.js/React в `src/astro/`), полностью покрывается vitest с
  фиксированной датой.
- `src/cards/MoonCard/` — текст + простая SVG-иконка фазы (терминатор —
  дуга эллипса по фазовому углу). Обновление раз в минуту таймером,
  `useApiResource` не нужен.

**Трудозатраты:** низкие; единственная карточка, работающая офлайн.

## 7. NASA Image & Video Library — поиск/подборка снимков

**Что:** компаньон APOD: поиск по архиву NASA или «случайный снимок по
теме» (Аполлон, туманности, Юпитер…).

**API:** `https://images-api.nasa.gov/search?q=<query>&media_type=image` —
без ключа, CORS `*`. В ответе `collection.items[]` с `links[0].href`
(превью) и `data[0]` (title, description, date_created).

**Реализация:**
- `src/api/nasaImages.ts` — обычный fetch+parse с валидатором.
- `src/cards/NasaImagesCard/` — вариант A: поле поиска + сетка превью;
  вариант B (проще): фиксированный список тем в
  `{ kind: 'multiselect' }`, карточка показывает случайный снимок из
  выбранных тем, кнопка «ещё».
- TTL поисковой выдачи — часы; можно кэшировать через `readCache` с
  предикатом.

**Трудозатраты:** низкие–средние (зависит от варианта UI).
