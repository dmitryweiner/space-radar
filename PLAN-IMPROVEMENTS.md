# План улучшений Space Radar: UX, единая сцена, новые источники

> Статус: **принят к исполнению** (решения заказчика от 2026-10-09 — в
> конце документа). Все внешние источники ниже проверены живым `curl` с заголовком
> `Origin: https://dmitryweiner.github.io` **2026-10-09** — проект остаётся
> статическим сайтом без бэкенда, поэтому CORS обязателен (или прокси из
> `backend-plan.md`).

Три жалобы пользователей и что за ними стоит:

| Жалоба | Корень проблемы в коде |
|---|---|
| На мобильных вместо прокрутки страницы крутится глобус в карточке | `OrbitControls` при подключении ставит на canvas `touch-action: none` и перехватывает одно-пальцевый свайп как вращение. Шапка карточки — drag-handle `react-grid-layout`, поэтому свайп по заголовку тоже не прокручивает, а тащит карточку. На телефоне глобусы занимают почти всю ширину — «безопасных» мест для свайпа почти нет. |
| Трудно сопоставлять информацию на разных карточках | Пять карточек рисуют **пять отдельных копий одной и той же Земли** (`createEarthScene` × 5): спутники, пожары, землетрясения, события EONET и аврора живут в разных сценах, каждая со своей камерой. Сопоставить «где сейчас МКС относительно овала сияний» невозможно по определению. Временные ряды (Kp, ветер, вспышки) тоже не связаны общей осью времени. |
| «Хочется, чтобы метеориты летели на нас прямо» | Астероиды — таблица из NeoWs (`close_approach_data[0]`): дата, промах, скорость. Ни одной геометрии нет, хотя NeoWs с `detailed=true` отдаёт кеплеровы элементы орбиты (проверено сегодня), а `astronomy-engine` уже умеет считать положение Земли. |

## Часть 1. UI/UX: от «решётки карточек» к «одна сцена + слои»

### 1.1. Решение: единая сцена как основной режим, дашборд — как второй

Рекомендую **не выкидывать карточки**, а добавить новый основной режим
«**Сцена**» (Scene) и оставить текущую решётку как режим «**Дашборд**»
(переключатель в шапке, выбор запоминается в `localStorage`). Причины:

- в дашборд вложено много рабочего кода и тестов (drag/resize/persistence,
  мобильная колонка, smoke-тесты) — его удаление ничего не даёт;
- не все данные «географические»: APOD, галерея NASA, графики Kp/ветра,
  солнечный цикл, Луна, Солнце в разных длинах волн — им на глобусе места
  нет, им нужно либо второе полотно (Солнце/Солнечная система), либо
  панели;
- режимы делят один слой данных (`src/api`, `src/hooks`, `src/astro`), так
  что поддержка двух UI сводится к двум наборам компонентов-обёрток.

**Макет режима «Сцена» (десктоп):**

```
┌──────────────────────────────────────────────────────────────────────┐
│ Space Radar   [Земля ▾] [Солнце] [Солн. система]    ⏱ 2026-10-09 07:21 │ ← шапка: выбор сцены + часы/скраббер
├──────────┬─────────────────────────────────────────────┬─────────────┤
│ СЛОИ     │                                             │ ИНСПЕКТОР   │
│ ☑ МКС    │                                             │ (детали     │
│ ☑ Спутн. │              ГЛОБУС (вся высота)            │  выбранного │
│ ☐ Пожары │                                             │  объекта,   │
│ ☑ Землетр│                                             │  легенда    │
│ ☑ EONET  │                                             │  слоя,      │
│ ☑ Аврора │                                             │  настройки) │
│ ☑ Астеро.│                                             │             │
│ ☐ Снимок │                                             │             │
│   GIBS   ├─────────────────────────────────────────────┤             │
│ ⚙ слоя   │ СТРОКА СОСТОЯНИЯ: Kp 3 · ветер 412 км/с ·   │             │
│          │ шкалы NOAA R0 S0 G1 · след. запуск через 4ч │             │
└──────────┴─────────────────────────────────────────────┴─────────────┘
```

- **Левая панель — слои.** Каждый сегодняшний «географический» источник
  становится слоем с чекбоксом, цветом и своей ⚙ (те же `settings` из
  `cardRegistry`). Все слои рисуются **в одной сцене на одном глобусе**.
- **Правая панель — инспектор.** Клик по маркеру (уже есть `setOnMarkerClick`
  и `MarkerInfoPopup`) открывает детали; там же легенда активных слоёв.
  На пустом выборе — компактные «виджеты» негеографических данных (Луна,
  Солнце 193 Å, APOD-превью, ближайшие запуски).
- **Строка состояния** внизу — числа «одним взглядом»: Kp, скорость ветра,
  шкалы NOAA R/S/G, число людей в космосе, следующий запуск. Клик
  раскрывает соответствующий график в инспекторе.
- **Три сцены**, переключаемые в шапке: *Земля* (все слои ниже), *Солнце*
  (SDO-снимок + активные регионы + вспышки/КВМ по времени), *Солнечная
  система* (существующая сцена + орбиты сближающихся астероидов).
- **Общий курсор времени (скраббер)** в шапке: «сейчас» по умолчанию;
  перетаскивание сдвигает *все* слои, которые умеют время (спутники по
  TLE, терминатор, положение Луны/Солнца, пролёты астероидов, кадры EPIC,
  графики подсвечивают ту же отметку). Именно он отвечает на «смотреть то
  туда, то сюда»: одна ось времени на всё.

**Макет на мобильных:** глобус на весь экран, слои — выдвижная «шторка»
снизу (bottom sheet), инспектор — та же шторка после тапа по маркеру,
строка состояния — горизонтально прокручиваемая лента чипов под шапкой.
Страница не прокручивается вообще, поэтому один палец свободно вращает
глобус — жалоба №1 в этом режиме исчезает по построению.

### 1.2. Быстрые исправления мобильного дашборда (делать первыми, независимо от 1.1)

Режим «Дашборд» остаётся, и его мобильные проблемы надо закрыть отдельно,
это 1–2 дня:

1. **Кооперативные жесты на глобусах** (как в Google Maps: один палец —
   прокрутка страницы, два — вращение/зум). В `createEarthScene` и
   `solarSystemScene` после создания `OrbitControls` на устройствах с
   `pointer: coarse`:
   - вернуть `canvas.style.touchAction = 'pan-y'` (OrbitControls ставит
     `none`);
   - одно-пальцевый touch не отдавать OrbitControls (`controls.touches.ONE`
     — не ROTATE; в коде без `as`-кастов, через переменную типа `TOUCH`);
   - при первом одно-пальцевом касании показать подсказку «Вращайте двумя
     пальцами» поверх canvas на 1.5 с.
   - В полноэкранном режиме карточки (`fullscreen-overlay`) прокручивать
     нечего — там оставить обычное одно-пальцевое вращение.
2. **Перетаскивание карточек на мобильном — только долгим нажатием** или
   через отдельную «ручку» `≡` в шапке карточки (`dragConfig.handle`
   меняется на `.card-drag-grip` при `isMobile`); у заголовка —
   `touch-action: pan-y`. Сейчас любой свайп по заголовку начинает drag.
3. **Колесо/пинч в прокручиваемых списках** (таблица астероидов, запуски):
   `overscroll-behavior: contain`, чтобы докрутка списка не дёргала страницу.
4. Smoke-тест: в `scripts/smoke.mjs` добавить сценарий с
   `hasTouch: true` (Playwright `touchscreen`): одно-пальцевый свайп по
   глобусу должен менять `window.scrollY` и **не** менять кадр
   (`countDiffPixels` < порога), двух-пальцевый — наоборот.

### 1.3. Архитектура единой сцены

Ключевая идея — **разделить «данные карточки» и «рендер карточки»**, что
по факту уже почти сделано (хуки `useApiResource`/`useTleSatellites` +
чистые `src/api`):

```
src/layers/                      ← новое
  types.ts         LayerDefinition { id, title, scene: 'earth'|'sun'|'solar-system',
                                     settings, useData(settings, time) → LayerFrame,
                                     legend, color }
  issLayer.ts      берёт логику из IssGlobeCard (TLE → позиции), отдаёт
                   { satellites: NamedPosition[] }
  quakesLayer.ts   { markers: GlobeMarker[] }
  firesLayer.ts    { firePoints: FirePoint[] }
  auroraLayer.ts   { auroraPoints: AuroraPoint[] }
  eonetLayer.ts    { markers }
  neoFlybyLayer.ts { flybys: FlybyTrack[] }           ← новое, см. часть 2
  gibsLayer.ts     { earthTexture: { url, date } }    ← новое
  terminatorLayer  { sunDirection }                   ← новое, чистая математика
src/render/earthScene.ts
  вместо setSatellites/setMarkers/… — `getLayer(id)` возвращает группу
  с теми же методами; слои независимы, можно включать по одному.
  Одна камера, один OrbitControls, один рендер-цикл на все слои.
src/scene/                       ← новый UI
  SceneView.tsx, LayerPanel.tsx, Inspector.tsx, StatusBar.tsx,
  TimeScrubber.tsx, sceneState.ts (+localStorage `space-radar:scene:v1`)
src/cards/*                      ← остаются; «географические» карточки
  становятся тонкими обёртками: useData слоя + своя сцена, как сейчас.
```

Что это даёт помимо UX:

- один WebGL-контекст вместо пяти (на телефонах пять контекстов —
  заметный нагрев и причина потери контекста);
- текстуры Земли загружаются один раз;
- `labelScale`/`rotateSpeed`/`earthStyle` из глобальных настроек
  применяются к одной сцене.

Риски: слои с подписями (спутники + пожары + землетрясения) вместе дают
визуальную кашу. Контрмеры: лимиты подписей на слой уже есть
(`labelCount`, `maxSatellites`), плюс приоритет подписей по важности и
скрытие подписей слоя при зуме дальше порога.

## Часть 2. «Летят на нас»: визуализация сближений астероидов

### 2.1. Что даёт NeoWs (проверено 2026-10-09)

`GET /neo/rest/v1/feed?start_date=…&end_date=…&detailed=true` — CORS `*`,
тот же ключ, и у каждого объекта есть `orbital_data`:
`semi_major_axis, eccentricity, inclination, ascending_node_longitude,
perihelion_argument, mean_anomaly, mean_motion, epoch_osculation,
orbital_period, minimum_orbit_intersection, orbit_class`. Плюс
`close_approach_data[]` с точным временем, промахом (км / лунные
расстояния) и относительной скоростью. Параметр `detailed=true` сейчас не
передаётся — это однострочное изменение в `src/api/neows.ts`.

### 2.2. Два уровня реализации

**Уровень A — схематичный пролёт (только из данных сближения, без орбит).**
Слой `neo-flyby` в сцене «Земля»:

- Земля в центре, **орбита Луны** как пунктирное кольцо для масштаба
  (384 400 км); шкала расстояний сжатая (`log` или `sqrt` от 1 R⊕ до
  0.1 а.е.), иначе Луна оказывается в 60 радиусах Земли и всё, кроме
  неё, не видно.
- Каждое сближение в окне ±N дней — прямая, проходящая мимо Земли на
  расстоянии промаха; по ней движется точка, положение = функция времени
  (относительная скорость × (t − t_сближения)). Размер точки по диаметру,
  красный цвет для `is_potentially_hazardous_asteroid`, хвост-трейл как у
  спутников (`trailLine.ts`).
- Скорость анимации: ×1 (реальное время — ничего не движется) ×1000 ×10 000
  — крутилка в инспекторе; скраббер времени из части 1 управляет тем же `t`.
- Направление прямой на уровне A — **условное** (случайный, но стабильный
  по `id` азимут), об этом честно сказать в легенде («схема, не реальная
  траектория»).

Оценка: 2–3 дня, целиком на существующей инфраструктуре `earthScene`.

**Уровень B — реальная геометрия (из `orbital_data`).**

- `src/astro/keplerOrbit.ts` — чистая математика: кеплеровы элементы +
  эпоха → гелиоцентрический вектор на момент `t` (решение уравнения
  Кеплера методом Ньютона, ~60 строк; `astronomy-engine` этого для
  произвольных элементов не умеет). Тест: элементы Земли → совпадение с
  `HelioVector(Body.Earth)` до 1e-3 а.е.; элементы известного астероида →
  расстояние до Земли в момент `close_approach_date_full` ≈ `miss_distance`.
- Геоцентрическая траектория = вектор астероида − `HelioVector(Earth)`
  на сетке времён ±N дней вокруг сближения → ломаная в сцене «Земля» (та
  же сжатая шкала). Направление подлёта, наклон траектории и то, с
  дневной или ночной стороны проходит объект, становятся настоящими.
- Та же функция даёт орбиты этих астероидов в сцене «Солнечная система»
  (линия орбиты + точка «сейчас»): видно, откуда объект прилетел.

Оценка: 3–4 дня. Точность для объектов с `orbit_uncertainty` ≥ 7 низкая
— показывать значение неопределённости в инспекторе.

### 3.4. Проверено и отброшено

- `api.nasa.gov/mars-photos` — Heroku-приложение удалено («No such app»).
- `api.nasa.gov/insight_weather` — миссия закончилась, данные 2020 года.
- `data.nasa.gov` (Socrata, набор «Meteorite Landings») — переехал, отдаёт HTML.
- `api.le-systeme-solaire.net` — теперь требует ключ (и не нужен: планеты
  считает `astronomy-engine`).
- SWPC `products/solar-wind/mag-1-day.json` — 404; живые аналоги —
  `json/rtsw/rtsw_wind_1m.json` и `rtsw_mag_1m.json`, но это 2.4 МБ и
  1.6 МБ за запрос — для **Bz** (ключевой параметр для сияний) лучше
  дождаться более лёгкого продукта или резать на прокси.
- COBS (кометы) — API есть, но параметры/лимиты нужно изучать отдельно;
  пока вне плана.

### 3.5. Что общего в реализации каждого источника

Чек-лист из `new-features-plan.md` остаётся в силе (чистый `src/api/*` с
инжектируемым `fetch`, валидатор-предикат без `as`, vitest-тест парсера,
строка в README). Дополнительно для нового UI:

- источник регистрируется как **слой** (`src/layers`) или **виджет**
  (`src/scene/widgets`), а не только как карточка;
- у каждого слоя `useData(settings, time)` — чтобы работал общий скраббер;
- большие ответы (S2, S4, S5, rtsw) прореживать при парсинге и кешировать
  уже прореженное — `localStorage` ограничен ~5 МБ на origin
  (`writeCache` уже глотает `QuotaExceededError`, но лучше туда не упираться).

## Часть 4. Состав релиза

Решение заказчика: всё ниже выходит **одним релизом**; прокси-воркер
входит в него (Cloudflare-аккаунт есть, `backend-plan.md` — готовая
инструкция). Порядок внутри релиза — по зависимостям, не по
«ценности»: пользователь ничего не увидит до деплоя, поэтому
фундамент идёт первым.

| Шаг | Что | Зависит от | Оценка |
|---|---|---|---|
| R1 | U1 — мобильные фиксы дашборда (два пальца вращают, drag долгим нажатием) + touch-сценарий в smoke | — | 1–2 дня |

В allowlist сразу добавить `ssd-api.jpl.nasa.gov` (cad/fireball/sentry), `api.spaceflightnewsapi.net`, `exoplanetarchive.ipac.caltech.edu`, GIBS не нужен (CORS есть) | — (параллельно R1) | 2–3 дня |
| R3 | U2 — `src/layers`: данные пяти глобус-карточек вынесены в слои, карточки — обёртки; `detailed=true` в `neows.ts` | — | 2–3 дня |
